## 0. 一句话结论

投研冲刺前向检验的不是"forced-flow 机制是否存在"，而是**"能否通过免费公开痕迹捕捉 forced-flow"**——后者被证伪，且死因是结构性的：**我们交易的从来不是强制流本身，而是强制流的公开痕迹；痕迹与本体之间必然存在一个由交易所机制设计决定的时间差 Δ，Δ 的符号决定死法（Δ<0 被抢跑，Δ>0 必迟到），而 Δ 不由我们的观测精度决定，因此换参数、换触发腿、换方向都救不活。**

这条结论**不外推**到量化 P0 forced-flow v2（见 §7——那条线观测的是本体不是影子，本次证伪反而强化了它的立项理由）。

## 2. 机制类一：funding/OI squeeze（"流影子"类）

### 2.1 假设演化史（三次修正，全部前向证伪）

1. **v1「深负 funding = 空头被挤压 = 做多」** → 003/005 败。诊断：深负 funding 是**必要非充分**——反复出现"空头付费且空头最终正确"（SAMSUNG/DATAIP/HOME/FLOCK/TOSHI 等）。
2. **v2「加导数腿区分回撤企稳 / 解体中继」**（005 结算推论，另立预登记无回溯）→ 006/007 首检即证伪。诊断：**导数腿没解决水平值不可区分问题，只把不可区分性从水平值搬到了导数上。**
3. **v3「反向下注：挤压耗竭做空」**（同一签名反读）→ 与 v2 同批判负。

三次修正把签名的读法穷尽了（多、空、加导数），**同一水平值签名在两个方向上均无前向 edge**。继续换触发腿即典型风险 D 局部修补搜索，故 07-24 裁决关闭该族前向登记。

### 2.2 死因：触发腿的结构性迟滞（ACE 尸检 + 6 例独立复现）

**ACEUSDT 尸检（2026-07-20/21）**：预设触发腿"连续 2 期实结 funding ≤ −0.3%"直到 07-20 20:00 UTC 才首次成立（实结序列 −0.484 / −0.204 / −0.497 / −0.298 / −0.565 / −0.530，隔期跳动），而彼时价格已自峰 −14.5%、OI 已自峰回落。

> **即：这条触发腿在 4h 结算档上系统性滞后挤压本体 4–8 小时。灯亮时行情已回吐。**

这**不是**巡检在场率问题（TOSHI 式漏接是另一回事，且已由防睡眠措施解决），是**触发腿本身的性质**。

**独立复现 6 例**：TREE / ZHIPU / ONE / MIRA / SHAZ / STXX——全部呈现 `premiumIndex 深负、实结 funding 平或转正` 的背离。预告费率（premiumIndex）看得见本体，实结 funding 看得见的是本体在结算时刻的**采样**。

**推论链（这解释了全部做多侧连败）**：

```
登记闸门 = 连续 2 期实结 funding
        ↓ 实结按结算周期采样（1h/4h/8h 档，档位差 8 倍）
闸门与机制发生窗口系统性错位
        ↓
前向样本被结构性筛选为「晚期挤压」
        ↓
003 追加速败（机制已走完）/ 005「企稳」实为解体（机制已走完）
```

### 2.3 为什么"换成 premiumIndex 触发"也救不活

这是我在 07-21 记录过、但当时未推到底的推论，现在补完：

premiumIndex 确实能消除 Δ（它是连续的，不受结算周期采样）。**但 premiumIndex 是 Binance 公开 API 免费实时提供给所有人的。** 换句话说，换掉滞后腿的代价是把我们放进一个**零信息优势**的赛道——所有人同时看到同一个数，且大资金的执行速度、成本、容量全面占优。

**Δ 的两难：Δ>0 时我们迟到；Δ→0 时我们没有任何理由比别人先动。** 这个两难不是参数问题。

## 3. 机制类二：日历型强制流（退市 / 解锁）

07-22 我曾判断这类"比 funding 挤压干净得多——付钱方是已知时刻的真·强制清算"。**07-24 两个活样本把这个乐观预期直接推翻，且两个死因不同。**

### 3.1 解锁：被电报式 front-run（Δ<0）

**H 解锁**（T0 = 2026-07-25 00:00 UTC，13.5% mcap / $17.24M）：闸 0 全过（占比 >3%、OI $16.2M、spread 3.5bp 可执行）。但 07-22 赖以看好的"无 price-in = 干净 setup"理据被证伪——**价格自 48h 高磨跌 −12% 至近低、funding 近 12 期全平**：这不是"没有 price-in"，是**持续被 front-run 的形态**。解锁时刻全网日历可查，抢跑窗口以周计。此时做空 = 追一段已经走完的下行。

附带发现：allocation 受益方明细 404 不可查 → **"谁在付钱、经什么路径"无法核实**，按机制优先七问这本身就不该登记。

### 3.2 退市：结算于 mark，无捕获窗（Δ 存在但不可交易）

**AERGO 合约退市**（2026-07-24 06:30 UTC 自动平仓）：T0 晨签名确实成形（实结 funding 翻**深正**且连加深 +0.44 → +0.64%/期 = 拥挤多头付费、价 +6.6% 近高、OI 自峰 −18%）——**这是本冲刺观测到的最干净的一次强制流签名**。

但不可登记，理由是结构性的：**退市结算价取 mark price，且结算后无永续可交易**。即使方向判对，也**没有一个可成交的窗口把判断变现**（<4h，且方向歧义：拥挤多头退市拉盘 vs 提前离场）。

> 这是一个重要的区分：**机制真实存在 ≠ 机制可交易。** 退市强制流是我们至今见过最真实的付钱方，但交易所的结算规则设计上不留捕获窗。

## 4. 反面证据核查（防止过度悲观）

诚实起见，以下反向问题必须问：

- **是否是登记闸门过严导致漏掉了真信号？** 反证：TOSHIUSDT 在巡检断档期出现完整三腿签名并在 20h 内死亡（07-18/19）——即使当时在场登记，按其后走势也是负样本。闸门不是漏了赢家。
- **是否是执行密度不够？** 反证：SG 哨兵 2h cadence、12 快照/日、连续 11 天 0 断档 0 source_errors、83 条拒绝分母。候选流从未是约束。
- **是否是样本太小以致无从判断？** **部分成立，这是本文档最大的诚实边界**——见 §8。
- **是否是我们不够勤勉？** 反证：约束在 07-21 就已从"候选流"转为"机制单一性"，且两类机制的死因都在**市场结构**层面而非工作量层面。

## 5. 共因归纳（本文档的核心，HYPOTHESIS 等级）

两类机制看似死于不同原因（一个迟到，一个被抢跑），但同构：

> **我们从未交易强制流本身，只交易强制流的公开痕迹。**
> **痕迹与本体之间存在时间差 Δ，由交易所机制设计（结算周期 / 公告制度 / 结算规则）决定，不由我们的观测精度决定。**

| | 痕迹 | Δ 符号 | 死法 |
|---|---|---|---|
| funding/OI squeeze | 实结 funding、OI 快照 | **Δ > 0**（痕迹晚于本体：结算是事后采样） | 灯亮时行情已回吐 |
| 解锁 | 日历公告 | **Δ < 0**（痕迹早于本体：公告先于事件） | 抢跑窗以周计，T0 已 price-in |
| 退市 | 公告 + 结算规则 | Δ < 0 且**结算于 mark** | 无可成交窗口，判对也不能变现 |

**Δ→0 的唯一途径（premiumIndex 类连续信号）会同时把信息优势归零**——因为能消除 Δ 的数据恰恰是免费实时公开的。

### 5.1 这对目标函数的直接含义

CLAUDE.md 机制优先七问第 ② 问：**"我们凭什么拿到（小资金的容量优势）？"**

对这两类机制，诚实答案是：**没有任何"凭什么"。** 免费 + 公开 + 时刻确定的信息，容量优势为零。我们此前的隐含答案是"我们更勤快、盯得更紧"——这不是容量优势，这是把勤勉当 alpha，正是 CLAUDE.md 明禁的路径。

**归因结论：失败应归于市场对免费可观测日历/流信号的效率，而非勤勉度或执行质量。**

## 6. 下一轮方向的筛选标准（本冲刺的可复用资产）

从 §5 反推，一个机制要有前向 edge 的可能，必须至少通过以下三问。**这三问建议加入未来所有 B0 机制卡的强制字段**：

**问 1：我们观测的是本体还是影子？影子的 Δ 由什么决定？**
- 若是影子且 Δ>0 由结算周期决定 → 直接否决，不必进入回测。
- 若能观测本体（逐笔成交/逐笔强平/订单流）→ 通过。

**问 2：若 Δ<0（日历型），为什么大资金没有把它抢跑到零？**
- 必须给出一个**具体的摩擦理由**：容量太小大资金不屑、合规限制、操作成本高、市场碎片化、数据获取有门槛。
- 答不出具体理由 = 默认已被抢跑到零，否决。

**问 3：判对之后有没有可成交窗口？**
- AERGO 教训：机制真实 ≠ 可交易。结算规则、流动性、spread、逆向 carry 必须在**登记前**核，不是结算时才发现（007 方向对但被 −3.96%/24h 逆向 carry 与成本吃光）。

**筛选标准的元性质：这三问全都在问"我们凭什么"，而不是"信号灵不灵"。** 这正是 DEC-064 研究顺序铁律（机制优先、自上而下）在事件类研究上的具体化。
