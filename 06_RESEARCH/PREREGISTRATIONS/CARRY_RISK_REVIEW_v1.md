## 1. 机制可信度：B

### 成立部分

1. §1 描述的“杠杆多头需求 -> 正 funding -> short perp 收款”在现行永续制度下有明确付款方、收款方和价格锚定机制。
2. §2 是持续持有 long spot/short perp，而非在极端 funding 后押注价格或 funding 反转；方向上已与 A-2 极端 funding 反转划开。
3. §1 明示 funding 可转负、协议/交易所事件和短腿强平，允许被证伪。

### 必改

1. 明文写出本策略**不以 funding 极端、价格反转或 funding 均值回归为 alpha**，所有正负 funding 时段均按冻结持仓规则计入；OI 只能是风险缩减件。
2. 将机制命题与策略命题分开。总净收益大于零不能证明收益来自 funding；必须冻结 funding、basis、再平衡、费用和事件损失的归因表，并要求“净 funding 贡献为正”才可声称 carry 机制成立。
3. 声明 edge 是**制度/状态依赖**而非永恒风险溢价：现货 ETF、更多做空工具、参与者结构和交易所 funding 公式变化均可能使长期均值转负。冻结机制失效报告口径（至少逐年及滚动 12 个月净 funding、公式变更分段），不得在结果后挑窗口。

## 2. 构造可复现性：D

1. “现货或 mark 近似”不是一个价格规则。mark 是永续风险/结算价格，不能同时充当现货成交价、delta 名义和 basis 测量价。必须指定现货数据源、venue、symbol、bar 对齐、缺失值和成交价；若缺现货数据，本研究不能用 mark 近似后仍声称测得 cash-and-carry basis。
2. 未冻结现货与永续是否同一交易所、USDT/币本位、保证金模式（逐仓/全仓）、保证金币种、maker/taker、资金划转及交易所最低维持保证金阶梯。
3. `N` 未定义为初始、当前目标还是组合分配名义；`|spot-perp|/N` 因此不可复现。再平衡由哪条腿完成、检查价/成交价、下单时点、恢复 100% 时的成交顺序也未冻结。
4. “保证金率 <=2x”混淆保证金率与杠杆。必须冻结初始杠杆、最大杠杆、保证金缓冲的计算式、补保证金来源、补仓时点和无法划转时的清算规则。
5. basis 的相关风险是路径内 mark-to-market、保证金挤压与最终收敛/退出损益，不只是进出场“滑点”。单个 `p95=+0.11%` 没有方向、负尾、最大值、事件条件或价源，不能支持“不对冲/可忽略”。

## 3. A-1×Carry 触发器：D

1. “6h 名义 OI 滚动分位 <=0.01”未说明变量是 OI 水平、6h 变化还是 6h 收益，也未冻结滚动/扩张窗口长度、最小历史、是否排除当前值、并列值、数据源和 bar 对齐。称为“骤降”却可能实际检验低 OI 水平。
2. 触发后是立即成交还是等每日 00:00 UTC，未说明；连续触发是否重置 24h、到期仍触发是否延长、恢复时是否一次性加回、BTC/ETH 同时触发时如何处理均不唯一。
3. “不显著恶化”不能用未拒绝差异来证明风控件无害。必须预登记**配对非劣检验**：同一路径有/无触发器、净收益差、非劣界值、单侧 alpha、同步块 bootstrap 与 seed。
4. “尾部改善”必须指定唯一指标和门槛，例如事件窗最大短腿保证金缺口、分档爆仓概率或组合 MDD 的预定改善幅度；不得结果后在 DD、ES、最差月等指标间择优。
5. 有/无触发器版只用于判定触发器是否保留；基础 carry 必须先独立通过全部硬门，禁止触发器版与无触发器版择优包装 edge。

## 4. 成本完整性：D

1. 应按每次成交分别计算 `spot_turnover` 与 `perp_turnover` 的 fee 和 slippage；当前 `2*fee_per_side*(开仓+平仓+再平衡换手)` 无法判断“2”代表两腿还是开/平，易重算或漏算。
2. 基准 `0.10%/边` 滑点只出现在参数行，没有进入公式；`basis_slippage` 不能替代逐腿交易滑点。
3. 事件触发减仓、24h 后恢复和强制退出都产生双腿换手。既然验收包含事件窗与事件驱动交易，须报告 `0.3%/0.5%/1.0%` 事件滑点压力档，而非只有 0.30%。
4. `perp_margin_financing(若有)` 不是冻结参数。必须写明保证金来源、借贷利率数据源/缺失处理；若完全自有资金，则固定为零，不保留事后选择。
5. 自有现货无需虚构借款利息，但必须把现货本金、永续初始保证金、闲置缓冲和事件备用现金全部计入 sleeve 资本分母。若现金基准冻结为 0，则不得再事后加入或删除无风险利率；若要计机会成本，须在预登记中统一替换基准。
6. 还需冻结资金费实际结算名义、交易所 funding 上限/下限与公式变更、手续费等级、ADL/破产损失、脱锚退出以及现货/保证金资产折价。

## 5. 验收闭合与统计功效：D

### 四件套未闭合

1. Protocol v1.3 要求“赢均/亏均 `>=1.5`”，§5 却只写无阈值的 `profit factor`；两者不是同一指标。
2. 分档爆仓概率整项缺失。核心 sleeve 至少必须按同步块 bootstrap 报：
   - 标准档 `P(年DD >=35%) <=20%`；
   - 保守档 `P(年DD >=20%) <=10%`；
   - 块长 1 周等效 bar 数、2000 条 1 年路径、固定 seed；
   - 路径内逐时检查短永续腿维持保证金/强平，而非只看组合收盘 MDD。
3. `E[R]` 的观察单位未定义。连续策略应冻结 8h funding interval、日或完整持仓 episode 中的一种，并据此定义赢/亏、名义分母和成本归属。
4. “几何增长 >0”须改为年化 log growth 的唯一公式；正年比例按 Protocol 的“多数”及有效年份口径执行，不能把当前 `>=3/4` 与别的标准并存。

### 依赖结构与 n_eff

1. 8h funding 强自相关，BTC/ETH 又同步相关。BTC、ETH 分开 bootstrap 后再组合会破坏共振尾部；必须对同步 UTC 的双资产向量做配对/多变量块重采样。
2. 序列层有效样本可报告
   `n_eff = n / (1 + 2 * sum(rho_k))`，
   但 ACF 截断规则、估计样本和最大 lag 必须预登记。该数字只能描述样本内序列精度，不能制造更多独立制度周期。
3. 2020-2024 约只有 4-5 个独立年度/制度阶段。以单侧 `alpha=0.05`、80% power 的一年一观测 t 检验计：

| 独立年度 `n_eff` | 最小可检测均值（相对年度收益 SD） | 年度 SD=5% | 年度 SD=10% | 年度 SD=15% |
|---:|---:|---:|---:|---:|
| 4 | `1.65 sigma` | 8.2% | 16.5% | 24.7% |
| 5 | `1.36 sigma` | 6.8% | 13.6% | 20.4% |

这些是未读取策略结果的功效计算。若合理净 edge 上限低于对应 MDE，按 Protocol v1.4 不得以该设计消耗独立计数。合理效应上限必须来自事前经济约束，不能用同一工作集已经观察到的 gross funding 反推。

4. 仅有 4 个独立年份时，即使 4/4 正年，精确单侧符号检验也只有 `p=0.0625`；`>=3/4` 为 `p=0.3125`。因此 8h block bootstrap 可以处理样本内自相关，却不能单独支持“跨制度长期显著为正”。

### 其他二元门缺口

1. `cluster/块 bootstrap` 没有 alpha、置信区间、块类型/长度、复制数、seed 和 cluster 单位。
2. WF“三段”没有边界、训练/验证职责、purge、余数和参数是否重估；`>=2 段正` 也不足以替代硬门的完整净验收。
3. 触发器的“显著恶化/尾部改善”无门槛，使 Decision Table 并不唯一。
4. 必须明文 `N.A. => FAIL`，并规定任一数据缺失、事件无法建模、强平概率无法计算时不得跳过。

## 6. 事件风险：D

1. “硬分叉/升级、提现暂停/暴雷、长时间脱锚”只是类别，不是冻结事件清单。必须列出工作集内每个事件的名称、venue/asset、UTC 起止、选窗规则；新发现事件只能按预先规则纳入，禁止结果后调窗。
2. ETH Merge 的单月结果已在预登记披露，不能再作为独立确认样本；其窗口选择也未冻结。
3. 组合 MDD 不能代表短腿不强平。long spot 的未实现盈利若不能即时、无摩擦转入 perp 保证金，短腿仍可能在急涨中先被清算。必须用 1h mark 或更细数据进行路径级保证金账本、维持保证金、补款延迟、ADL/交易暂停和 basis 扩张压力测试。
4. 事件压力下的强平概率和事件窗 MDD 必须进入 §5 硬门，不得只作附表或口头讨论。

## 7. Holdout 与计数：C

1. `<2024-12-10` / `>=2024-12-10` 的时间切分和“sleeve 上线属于 D 级”清楚。
2. 边界只点名 funding/价格，遗漏 OI、事件标签、费率/保证金阶梯等会影响策略的输入；所有输入必须使用同一 cutoff 和封存清单。
3. “同 A-1 v5 §12”必须锁定准确文件路径、版本/SHA 和负向权限测试，不能依赖可变外部段落。
4. “盲审 + Founder 确认前不读”暗示之后可读，不符合执行身份不得接触 Holdout 的永久边界。应冻结 custodian、加密/ACL、执行身份负向测试、何种独立评估身份可在何种决策后解封；研究执行者任何情况下不可读。
5. 由于设计参数已经从工作集结果产生，工作集 PASS 最多支持“锁定历史可行性复核”，不能直接计作独立机制确证并上线。核心资本放行至少需要未参与设计的数据或前瞻 shadow/live 确证，并另行预登记。
