## 详细判断

### 1. A-2 非重叠关联门

v5 §7 L121 同时完成名称和解释边界修正：non-overlap 显著只支持“A-1 关联不完全由 A-2 正极端 funding 重叠承载”，并明确“不识别独立机制”。§0、§1、§9 和 §13 继续把结论上限锁在关联层，把强平机制确证留给前向路径 B。

因此 RR4 #1 完全闭合。

### 2. Circular bootstrap 与 Spearman

§4 L78 把时间轴冻结为半开 UTC 小时网格 `[t_1, t_n+1h)`，周长为 `(t_n-t_1)+1h`，消除了首尾 episode 映射到同一圆周点的问题。§4 L81-L83 使用

```text
off_i(u) = ((event_time_i - u) mod span)
```

定义块成员，并按 `off_i(u)` 而非绝对 `event_time` 对最后一块排序和截断，跨尾端回绕时仍从随机起点 `u` 向前保持正确顺序。

§5 L97 不再称为标签置换，也不再独立重排 severity。它对 `(severity, CAR_48h)` 配对序列使用同口径 circular moving-block bootstrap，保留配对关系和时间依赖。

该居中检验确实对应 `H0: rho=0`：观测检验统计量为 `rho_obs-0`，bootstrap 估计的抽样误差为 `rho*-rho_obs`；单侧尾部

```text
P_bootstrap(rho* - rho_obs >= rho_obs - 0)
```

正是 v5 冻结的计数式。它是依赖保持的 bootstrap 零假设检验，不是精确置换检验；按本关联快筛标尺足够且与所写零假设一致。

因此 RR4 #2 完全闭合。

### 3. WF

§11 L160 的段长公式对三种余数情形给出唯一结果：

| `n mod 3` | 三段长度 |
|---:|---|
| 0 | `(q, q, q)` |
| 1 | `(q+1, q, q)` |
| 2 | `(q+1, q+1, q)` |

这与“余数先给第一段、再给第二段”一致。切点固定为相邻两 episode `event_time` 的算术中点；§12 L171 又冻结原始确定性排序为 `(event_time_utc, symbol)`，可处理同一时点跨品种 episode 的顺序。

purge footprint 已从 v4 的 `event_time+48h` 改为 `[event_time-72h, align+48h]`，覆盖 §2 的入场对齐 lag；跨任一切点的 episode 从原段剔除，且明文禁止重新分段或重新等分。必要项出现 N.A. 时由 §11 L165 统一判 FAIL。

未发现会改变 WF 判决的剩余实现自由度。因此 RR4 #3 完全闭合。

### 4. Holdout

§12 L172 冻结认证加密为 AES-256-GCM，并冻结文件布局、nonce/tag 长度和 tag 认证失败判据。密钥的安全属性也已完整写明：只存在于正式执行身份不可访问的主会话 secret、独立 OS principal 或 ACL 限定位置，且不得进入 Codex 可读文件、环境变量、命令行或日志。

§12 L174 要求在正式执行身份下记录：

1. manifest 读取命令及退出码 0；
2. sealed 解密命令、非零退出码和密钥不可得/拒绝访问或 GCM 认证失败证据。

这不再是“移出 workspace”的路径约定，而是“密文可见、解密能力由独立权限主体控制”的读权限边界。设计层面成立；若封存或负向测试未实际完成，则依 §11 L161-L165 不得放行。

因此 RR4 #4 完全闭合。
