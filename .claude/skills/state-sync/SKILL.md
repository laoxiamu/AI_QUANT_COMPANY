# State-Sync：对话级状态同步

## 为什么这是制度问题，不是注意力问题

项目历史上的漏记原因：对话结束前没有强制检查点。DEC-073 要求每轮对话的所有建议、决策、任务状态变更必须当场写入权威文件。本 skill 是这个制度的执行工具。

## 触发条件（遇到任何一项即执行）

- 任务完成或失败（PROJECT_TASK_PLAN 状态变更）
- 研究结论产出（机会地图/墓园更新）
- 建议或方案提出（写入 CURRENT_STATE §1c）
- 阻塞解除（更新任务书阻塞状态）
- Founder 做了 D 级确认（写入 DECISION_LOG）
- 对话接近结束（§1b 更新恢复点）

---

## 同步流程

### Step 1：盘点本轮变化（30秒强制回顾）

列出本轮对话中发生的所有变化：

```
变化清单：
□ 完成的任务（任务ID + 产物路径）
□ 新发现的阻塞或解除的阻塞
□ 提出的建议/方案（未经Founder确认的）
□ Founder 确认的 D 级决策
□ 研究结论变更（机会地图/墓园）
□ 下一步恢复点（下次对话从哪里继续）
```

### Step 2：按文件逐项写入

#### CURRENT_STATE.md（固定槽位覆盖式）

| 槽位 | 什么时候更新 |
|---|---|
| `在途任务` | 任务完成/阻塞状态变更 |
| `§1b 活动工作区` | 每次对话结束前必须更新恢复点 |
| `§1c 对话级建议暂存区` | Claude 提出任何建议，立即写入 |
| `等待Founder` | D 级项数量变化 |

**§1b 标准格式：**
```
**{日期}（本轮对话={主要工作}，{状态}）**：✅已完成：{列出} 🔴未完成：{列出} 
**新对话首要任务（按优先级）**：①{任务} ②{任务} ③{任务}
```

**§1c 标准格式（每条建议）：**
```
**{序号}【{类型}D级/建议】** {建议内容}。推荐={是/否/具体建议}。
```

#### PROJECT_TASK_PLAN.md（任务状态行）

只改对应任务行的"状态"列和"下一步"列，不改其他内容。
- 完成：状态改为 `✅完成`，产物/证据列填入文件路径
- 阻塞：状态改为 `🔴阻塞`，下一步列写明阻塞源和解除条件
- 新增：最后添加新行，状态为 `🔵新增`

#### DECISION_LOG.md（仅在 Founder 做了 D 级决策时写入）

DEC 编号格式：`DEC-{三位数}`，在现有最大编号+1。
写入位置：文件头部索引 + 完整条目。

#### BOOT_BRIEF.md（仅在关键状态变化时更新）

更新以下字段：
- `一句话现状`：如果阶段或主线发生变化
- `在途与等待`：如果阻塞状态变化
- 最后更新日期

---

## Step 3：验证

写入后验证：
1. CURRENT_STATE 不超过 150 行（规定上限）
2. §1b 含明确的"新对话首要任务"
3. §1c 没有遗漏本轮提出的建议
4. PROJECT_TASK_PLAN 对应任务行状态已更新

---

## 快速检查表（每次对话结束前 1 分钟）

```
□ §1b 已写新对话恢复点？
□ §1c 本轮所有建议已写入？
□ PROJECT_TASK_PLAN 已更新完成/阻塞任务？
□ 有 Founder D 级确认需写 DECISION_LOG？
□ 机会地图/墓园有变更需写 OPPORTUNITY_MAP_STATUS？
□ BOOT_BRIEF 需更新（一句话现状/在途）？
```

全部勾选 → 对话可以结束。有未勾 → 先补写。

---

## 优先级规则（冲突时）

DECISION_LOG > CURRENT_STATE > PROJECT_TASK_PLAN > BOOT_BRIEF

即：先写 DECISION_LOG（有D级决策时），再写 CURRENT_STATE，再更新任务计划，最后更新 BOOT_BRIEF 派生摘要。
