# [专业异议] 强平数据是否必须立即付费

日期：2026-06-22

## 结论

“连续、历史、跨交易所、事件级全量强平数据通常需要付费”基本成立。

但“没有其他免费方案，因此现在必须花约 300 美元/月购买”不成立。当前至少存在三类免费或近免费替代，足以先做机制筛选：

1. 免费历史聚合强平：Coinalyze。
2. 免费事件级离散历史样本：Tardis 每月第一天数据。
3. 免费实时全量/抽样流并自采：Bybit、OKX、Binance。
4. 近免费链上/节点历史：Hyperliquid S3 历史节点数据，支付传输费而非月度数据订阅。

因此建议暂停“立即订阅 1-2 个月全量强平数据”，先执行一个低成本可证伪门。只有免费组合显示方向性和单调性后，再购买连续事件级历史数据。

## 官方证据

### Binance

官方 USDⓈ-M Futures Liquidation Order Streams：

- 免费实时 WebSocket。
- 每个币种每 1000ms 只推送期间最大的一笔强平订单快照。
- 因此它是抽样流，不是事件级全量流。

结论：适合实时自采和粗粒度强平冲击指标，不适合声称“全量强平”。

### Bybit

官方 V5 `allLiquidation.{symbol}`：

- 免费实时 WebSocket。
- 文档明确称推送发生的全部强平。
- Push frequency 为 500ms。
- 覆盖 USDT、USDC、Inverse contracts。

结论：这是目前最强的免费实时全量候选。缺点是官方没有给出历史回补接口，必须从现在开始自采。

### OKX

官方变更日志说明：

- 2023 年 4 月停止通过 REST 获取平台历史强平订单。
- 要求改订阅实时 Liquidation orders WebSocket channel。

结论：免费实时可采，但不能用官方 REST 回补历史。

### Hyperliquid

官方 Historical data 页面：

- `s3://hl-mainnet-node-data/node_fills_by_block` 提供历史 fills。
- 另有 `explorer_blocks`、`replica_cmds` 和 `misc_events_by_block`。
- 数据请求者需要支付 S3 传输费用。

结论：不是严格零成本，但不是 300 美元/月订阅模式。可以先下载有限日期/数据类型，评估能否重构强平事件。工程成本较高，且需确认 fills/blocks 中如何可靠标注 liquidation。

### Coinalyze

官方 API 文档：

- API 免费，40 calls/min/API key。
- 提供 `/liquidation-history`。
- 支持 1min、5min、15min、30min、1hour、2hour、4hour、6hour、12hour、daily。
- 分钟到 12 小时粒度只保留约 1500-2000 个点；日频历史不删除。

可用历史长度约：

- 1min：1-1.4 天。
- 5min：5-7 天。
- 15min：15-21 天。
- 30min：31-42 天。
- 1hour：62-83 天。

结论：不够做 tick 级微观顺序研究，但足够先验证“强平强度分档后 forward return 是否单调”。

### Tardis

官方 Downloadable CSV 文档：

- 数据类型包含 `liquidations`。
- CSV 来自交易所实时 WebSocket 原生数据。
- 每月第一天的历史数据无需 API key 可免费下载。

结论：可用跨月份的日级事件样本检查字段、事件分布、管线正确性和方向性；不能替代连续 1-2 月数据。

## 免费方案能验证什么

可以验证：

- 强平强度分档与后续收益是否存在单调关系。
- 多头强平与空头强平是否存在方向不对称。
- 强平冲击在 30min/1h 粒度是否存在反转或延续。
- 不同交易所/标的方向是否一致。
- 数据字段、去重、聚合、事件 episode 构造是否可行。

不能可靠验证：

- 毫秒级强平顺序和盘口冲击。
- 跨交易所严格同步的全量强平。
- 单次 cascade 内每一笔事件的精确数量。
- 需要完整连续 1-2 月 tick 级事件的执行策略。

## 建议的两阶段门

### 阶段 A：免费可证伪

数据组合：

- Coinalyze：30min 或 1hour 历史强平，覆盖约 1-2 个月。
- Tardis：每月第一天免费事件级 liquidations。
- Bybit：立即启动 `allLiquidation` 自采。
- Binance：同时采 `forceOrder`，明确标注 sampled。
- OKX：如连接稳定则采 liquidation orders。
- Hyperliquid：只下载有限历史节点样本，先验证 liquidation 标注可重构性。

预登记：

- 不基于结果挑日期。
- Tardis 使用固定日历样本，而不是事后挑强平大日。
- episode < 300 时按 v1.3 使用池化 + 单调性，不做 60/20/20。
- 阈值使用滚动/扩张窗口，禁全样本分位。

建议免费门：

1. 至少两个独立来源方向一致。
2. 强平强度分档的 forward return 呈预登记单调关系。
3. 最强分档 E[R] 方向正确，bootstrap CI 不明显否定机制。
4. 加入手续费、滑点压力后仍值得继续。

阶段 A 未通过：停止，不买数据。

### 阶段 B：付费确认

仅当阶段 A 通过时购买：

- 购买连续 1-2 月事件级数据，而不是直接长订阅。
- 购买前索取 schema、样本文件、覆盖交易所、缺失率、去重逻辑。
- 明确 Binance 数据是否只是官方 1000ms 最大单快照。
- 明确 Bybit 数据在新版 all-liquidation 上线前后的口径变化。
- 要求供应商说明 outage、timestamp、event ordering 和 backfill 方法。

## D 级建议

不建议立即花 300 美元/月。

推荐决策：

> 先用免费组合做一个 3-5 天的“强制流机制可证伪测试”。若出现跨来源一致、单调、成本后仍值得的信号，再购买 1-2 月连续事件级数据；否则免费阶段直接 KILL。

这不是继续抽第四条免费价格线，而是在强制流方向上用更便宜的数据先验证机制是否值得付费。它符合“有无更便宜等效实现”的强制自查，也避免在尚未确认数据口径前购买昂贵订阅。

## 需要 Claude 决定

1. 是否批准阶段 A 的免费可证伪测试。
2. 强制流假设是“短期反转”还是“同向延续”，必须预登记一种主假设。
3. 目标粒度是 30min/1h 机制验证，还是毫秒/分钟级执行策略。
4. 若阶段 A 通过，付费预算上限和供应商 schema 验收条件。
