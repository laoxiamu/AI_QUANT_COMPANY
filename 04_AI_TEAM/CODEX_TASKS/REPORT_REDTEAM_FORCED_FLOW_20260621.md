## 总裁决

**总裁决：ACCEPT-with-MODIFY，但当前 B0 的 `PROCEED 到 B1（建议 OFI 先行）` 判定过宽，必须降级为 `REVISE_ONCE`。**

强制/激进流作为机制家族有真实 payer，但 B0 当前把两个高风险子机制放得太宽：

1. **清算流路径**高度继承 A-1 失败与免费强平数据旧伤，不能用“方向不预设/时间尺度不同”轻易脱钩。
2. **OFI 先行路径**在项目成本模型下大概率过不了经济功效门：分钟级公开订单流的合理可捕获效应上限很可能低于 0.1%/边手续费 + 0.1%/边滑点后的交易成本。
3. **形态触发器**若不机械限制，极易从“机制观测量”滑回 Sweep 式看图调参。

我的建议不是直接杀掉整个强制/激进流方向，而是杀掉 **“按当前 B0 直接推进 OFI 或免费强平流 B1”**。B1 若要继续，必须改成一个更窄的 **数据-功效 Kill Card**，先证明可检测、可交易、可审计，再允许进入 B2。

## 1. A-1 换皮风险

**结论：B0 §2 的三点区分只对“纯订单流 OFI”部分基本成立；对“清算流延续/耗尽”部分不充分。清算流路径有高换皮风险。**

### 1.1 “方向不预设”并不自动脱离 A-1

A-1 测的是 `OI 骤降 + 同窗负收益 -> 48h 回弹`，本质是“强制去杠杆后是否存在可交易漂移”。B0 新线若定义为“清算簇后延续或耗尽由数据决定”，仍然是在同一事件家族上检验事后漂移，只是把方向从单边回弹改成双向待选。

这不是无效改进，但它有一个红队问题：**如果 B1/B2 同时允许延续与耗尽两种方向进入候选，再按显著性或净收益选方向，就等价于把 A-1 的单边假设扩大成双边搜索。** 这会把“方向不预设”变成更宽的研究自由度，而不是机制区分。

机械要求：清算流若继续，B1 必须在看任何收益结果前冻结一个方向命题，例如“清算方向延续”或“清算后耗尽反转”，不能两头都试后择优。

### 1.2 “数据更直接”只部分成立

清算流：不成立。B0 承认 Binance 免费 `forceOrder` 是抽样广播/截断，墓园 A-1 已把“前向真实强平路径”降为休眠免费期权，需 3-6 月数据积累。所谓更直接，如果仍使用免费强平流，不等于更可靠；只是从 OI proxy 换成一个缺失机制未知的截断观测。

订单流：成立但不够。`aggTrades` / 深度 WS 确实比 OI proxy 更直接，但这只能证明“能观察 taker 与盘口变化”，不能证明扣成本后还有可捕获 edge。

### 1.3 “时间尺度不同”是必要但不是充分区分

48h 回弹失败确实不直接杀死秒-分钟效应。但它给出强烈反证：如果强制流存在，其可交易窗口很可能极短、成本极敏感、被执行质量主导。换言之，A-1 的失败不是完全遗传收益方向，但会遗传三类核心问题：

1. 强制流事件稀疏，统计功效与 regime 聚集问题仍在。
2. 免费清算数据缺失/截断，机制归因仍不干净。
3. 级联附近滑点上升，事件成本压力档仍可能吞掉全部毛边际。

**继承比例判断：**

- 清算流延续/耗尽：继承 A-1 风险约 70%-80%。机制家族、事件定义、数据旧伤、成本压力高度重合。
- 纯 OFI：继承 A-1 风险约 20%-30%。不是 A-1 换皮，但有自己的 MDE/成本死刑。
- “清算 + OFI + 形态触发器”混合：继承风险重新升高到 80% 以上，因为它会同时打开 A-1 和 Sweep 的两条旧失败路径。

## 2. OFI 的 MDE 死刑

**结论：按当前项目成本模型，B0 不能把 OFI 判为“建议先行”。OFI-first 应在 B0 被判 `KILL_AS_TRADABLE_SIGNAL`，除非 B1 先证明它在非共置、分钟级、全成本后仍有合理效应上限。**

### 2.1 成本门槛过高

项目标准成本是手续费 0.1%/边 + 滑点 0.1%/边。若 OFI 信号需要 taker 进出，单次往返成本约为：

`0.1% fee in + 0.1% slippage in + 0.1% fee out + 0.1% slippage out = 0.4%`

分钟级公开 OFI 的合理可捕获毛效应通常应按 bps 级思考，而不是 40bp 以上。B0 没有给出任何依据说明：

1. 非共置 Binance 公共 WS 延迟后仍能捕获 >40bp 的平均毛漂移；
2. 信号不依赖极端波动窗，而极端窗滑点不会超过基准；
3. 退出不需要再次付 taker 成本；
4. 高频换手不会让少数大样本显著性变成经济负期望。

因此，红队先验是：**OFI 的合理效应上限 < 全成本门槛**。这比“统计 MDE 是否足够小”更致命。

### 2.2 MDE 可能统计可检，但经济不可交易

分钟级样本量大，统计 MDE 可能很小；但 Protocol v1.4 的功效门要求比较的是“最小可检测效应”与“合理效应上限”。这里必须加入交易成本后的经济阈值。否则会出现一个危险结论：n 很大所以能显著检测到 1-3bp 的 OFI 漂移，但项目实际每轮要付约 40bp 成本。

B1 不应只报告 `MDE <= gross_effect_upper_bound`，还必须报告：

`MDE <= max(0, gross_effect_upper_bound - all-in tradable cost)`

若 gross upper bound 低于全成本，B1 应直接 KILL，不进入 B2。

### 2.3 B0 对 OFI 的正确处理

我建议改写为：

> OFI 不作为 B1 首选 Alpha 子机制；仅允许做不耗计数的数据/功效审计。若不能在预登记前用外部先验或自采样本证明“非共置分钟级、全成本后合理效应上限 > 0 且 MDE 不高于该上限”，OFI 路径 KILL。

## 3. 数据门

**结论：清算流的数据门是当前 showstopper；订单流的数据可审计但交易可行性是 showstopper。**

### 3.1 清算流：showstopper

Binance 免费 `forceOrder` 的问题不是普通噪声，而是抽样/截断。红队不能假设缺失是随机的；更可能在高压窗口、极端拥堵、不同币种间呈系统性缺失。这会直接污染三个核心变量：

1. 清算簇规模；
2. 清算方向与价格冲击先后关系；
3. 严重度分档单调性。

没有全量强平源或足够长的前向一致采集，清算流 B1 只能做数据 readiness 审计，不能做机制确证预登记。

**判定：免费清算流不能支撑 B2。若无付费全量源或 3-6 月以上前向完整采集，清算路径 KILL/休眠。**

### 3.2 订单流：数据审计可做，但不是 Alpha 通过证据

`aggTrades` 的 taker 方向标注本身相对可审计，Binance 的 buyer-is-maker 字段可以转换主动买/卖方向。主要风险不在“方向字段完全不可用”，而在：

1. 聚合成交会压缩 tick 级顺序信息；
2. 深度增量重建需要 snapshot、update id 连续性、gap repair、延迟记录，否则 MLOFI 很容易错；
3. 公开 WS 的本地到达时间不是交易所撮合时间；
4. 可离线重建的 OFI 不等于可实时执行的 OFI。

**判定：订单流数据门不是 showstopper；但“用它做分钟级可交易 Alpha”在成本/延迟门上是 showstopper。**

## 4. 防“形态触发器”滑回 Sweep 搜索

**结论：B0 的“形态只作触发器”口径仍危险。触发器一旦参与方向判定或样本筛选，就会实质变回 Sweep/SMC 家族。**

B1/B2 必须有一个机械防滑回判据：

> **B1/B2 的入组触发、方向判定、分层变量，只允许使用预先列明的流变量：清算 notional、signed taker volume、OFI/MLOFI、深度不平衡、spread、realized volatility/OI 控制项。任何使用局部高低点、支撑阻力、突破回踩、插针、影线、sweep、结构位、K线形态、均线形态作为入组或方向条件的设计，一律判为 Sweep-family 复活，直接 KILL。**

进一步要求：

1. 价格只能作为结果变量、成本/波动控制变量或被动基准，不得作为形态触发器。
2. 如果删掉形态条件后机制信号不成立，不能把形态条件加回去“提高胜率”。
3. B2 每个子机制最多一个主信号、一个预先冻结方向、一个预先冻结持有窗族；不得在触发器、方向、窗口三处同时自由搜索。

## 5. PROCEED 是否应降级

**结论：应从 PROCEED 降级为 REVISE_ONCE。**

当前 B0 的问题不是“方向完全没 payer”，而是把“payer plausible”误推进为“可以 B1 选 OFI 并准备 B2”。这一步过宽。

我建议的修订版 B1 不应叫“子机制选定 + 数据/标签审计”，而应叫：

**P1-RES-036-B1-KILLCARD：强制/激进流数据-功效门**

必须先做四个非收益筛查：

1. **成本可交易性门：** 对每个候选子机制给出全成本 break-even drift；若合理毛效应上限低于成本，KILL。
2. **数据完整性门：** 清算流证明全量或缺失机制可界定；订单流证明 L2 book 连续重建、延迟记录、方向字段一致性。
3. **反 A-1 门：** 清算路径必须冻结一个与 A-1 不同的、单向可证伪命题；不得“延续/耗尽”两头测。
4. **反 Sweep 门：** 触发与方向变量白名单化，禁止价格形态入组。

若 B1-KILLCARD 过不了，方向应回墓园/休眠，不应进入 B2。

## 6. 有没有更高信息增益的第三子机制

**结论：严格在“免费 Binance 强制流/OFI”范围内，没有一个明显更干净且 payer 更硬的第三子机制。若必须继续强制/激进流家族，信息增益更高的替代是：跨市场 aggressive-flow price-discovery lead-lag，但只能作为 B1 候选，不应直接当 Alpha。**

候选定义：

> **Spot-perp / venue lead-lag under aggressive flow：** 当现货或主导 venue 出现单边 aggressive flow 与价格冲击，永续或滞后 venue 在非超低延迟窗口内是否存在可捕获补价漂移。

为什么它比当前两个子机制更适合作为 B1 候选：

1. 数据更干净：spot/perp trades、books、timestamps 可公开采集，缺失问题小于免费强平流。
2. payer 更明确：滞后 venue 上需要追价的 taker / hedger 支付冲击成本。
3. 与 A-1 重叠更低：不是清算后回弹，不继承 OI proxy 失败。
4. 可快速证伪：若 1min 以上、非共置延迟、全成本后没有漂移，直接 KILL。

风险同样很大：它贴近延迟套利边界，可能已被专业基础设施吃掉；因此 B1 必须明确排除 tick 级/共置竞速，只允许秒-分钟级、可由项目真实系统执行的窗口。

如果 Claude 不接受这个第三候选，那么我的建议是：**不要强行从 OFI/清算里挑一个先做；把强制/激进流方向休眠，回到机会地图其他候选。**

## 最终建议

1. **否决当前 B0 的 PROCEED 文案。**
2. **KILL OFI-first as tradable alpha under current assumptions**，除非 B1 先证明经济效应上限扣成本后仍为正且 MDE 可检。
3. **清算流转为休眠/数据积累**，无全量强平源或足够前向采集前不得进入 B2。
4. **若继续，重写 B1 为 Kill Card**，目标是尽快杀死不可交易路径，而不是选择最顺眼的子机制。
5. **第三候选可考虑 spot-perp/venue aggressive-flow lead-lag**，但必须带非共置、秒-分钟、全成本、反延迟套利边界。

一句话：**方向不必立刻 REJECT，但当前 B0 的“OFI 先行 + 清算并行攒数据”太乐观；按纪律应 REVISE_ONCE，且默认以 KILL 为基线。**
